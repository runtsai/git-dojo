## Findings (ranked by severity)

### HIGH

**H1. Unauthenticated progress mutation — CONFIRMED**
- File: `artifacts/api-server/src/routes/progress.ts:33-69` (`POST /progress/complete`)
- Evidence: `router.post("/progress/complete", (req, res) => { ... })` — no `requireOwner`, no `rateLimit` (grader routes in `dojo.ts` have both).
- Defect: any reachable caller can mark any visual module complete, corrupting course progress and unlocking gated state. On the published site the API is publicly reachable.
- Fix: apply `requireOwner` (and a modest rate limit), matching the pattern already used on `dojo.ts:227` and `:277`.
- Effort: S

**H2. Unauthenticated drill mutation — CONFIRMED**
- File: `artifacts/api-server/src/routes/drills.ts:18-35` (`POST /drills/due`, `POST /drills/attempt`)
- Evidence: routes registered with no auth/rate-limit middleware.
- Defect: anyone can spam attempts, mutating spaced-repetition history/scheduling and causing storage churn.
- Fix: same `requireOwner` + `rateLimit` treatment.
- Effort: S

**H3. Concurrent crisis setup race can corrupt the practice repo — CONFIRMED**
- File: `artifacts/api-server/src/routes/crisis.ts:58-65` (via `:445-453`)
- Evidence: `rmSync(pg, { recursive: true, force: true }); mkdirSync(...)` followed by async `mustGit` calls, with no per-scenario lock.
- Defect: two overlapping setup POSTs interleave `git init`/writes/commits in the same directory; one can delete the other's repo mid-operation, leaving a broken or mixed scenario.
- Fix: serialize setup per scenario (in-process queue) or build in a temp dir and atomically rename; also add a rate limit (setup is expensive filesystem/git work and currently unlimited).
- Effort: M

### MEDIUM

**M1. Crisis setup failures return HTTP 200 — CONFIRMED**
- File: `artifacts/api-server/src/routes/crisis.ts:461-468`
- Evidence: the catch block calls `res.json({ ok: false, ... })` without an error status.
- Defect: status-checking clients/monitors treat a failed disaster setup as success, then hit missing state.
- Fix: return 5xx with the structured body. (Related to queued task "API signals degraded with HTTP 503", but that covers the health route — this is the setup route.)
- Effort: S

**M2. Async GET handlers lack an error boundary — CONFIRMED**
- Files: `artifacts/api-server/src/routes/dojo.ts:96-118, 153-171`; `crisis.ts:420-443, 472-486, 489-510`
- Evidence: async handlers call `listLessonDirs` / `readRepoState` / Zod parsing with no try/catch and no async-error middleware.
- Defect: a vanished directory or unexpected git/Zod failure rejects the handler; Express does not forward it, leaving the request hanging plus an unhandled rejection.
- Fix: add an async-handler wrapper or global error middleware; map expected FS failures to 404/5xx.
- Effort: M

**M3. Core dojo/drills/promo-meta API routes have no route-level tests — CONFIRMED**
- Files: `artifacts/api-server/src/routes/dojo.ts:96-277`, `drills.ts:18-27`, `promo-meta.ts:13`
- Defect: the primary course browsing/grading/bot flow and the drills contract can regress undetected (unit tests cover libs, not these HTTP routes).
- Fix: supertest-style route tests: success, malformed ids, auth, rate limit, grader failure.
- Effort: L

**M4. Diff modal lacks focus management — CONFIRMED**
- File: `artifacts/git-dojo-dashboard/src/components/repo-view/diff-viewer.tsx:137-169`
- Evidence: `role=dialog`/`aria-modal` and Escape handling exist, but no initial focus, no Tab trap, no focus restore.
- Defect: keyboard/screen-reader focus stays behind the modal; closing strands focus.
- Fix: use the Dialog primitive or add focus trap + restore.
- Effort: M

**M5. Map journey overlay is modal-like without dialog semantics — CONFIRMED**
- File: `artifacts/git-dojo-dashboard/src/pages/map.tsx:195-217`
- Evidence: fixed overlay panel with Cancel/Next; no role, aria-modal, focus handling, or Escape.
- Fix: dialog semantics + focus management as in M4.
- Effort: M

**M6. Lesson 08/09 graders verify outcome, not the taught workflow — CONFIRMED (design gap, not learner-facing breakage)**
- Files: `git-dojo/lessons/lesson-08-the-collision/check.sh:8-10` vs README:37-54; `lesson-09-the-standoff/check.sh:8-11` vs README:34-42
- Evidence: READMEs teach `git fetch` → inspect (`git log main..origin/main`, `git diff main...origin/main`) → `git merge origin/main`; graders check only final tips/history and accept `git pull`.
- Defect: a learner can skip the entire inspection workflow the lesson exists to teach and still PASS.
- Fix: either state explicitly that only the outcome is graded, or add checks distinguishing fetch+merge evidence.
- Effort: M

**L10. Content wording inaccuracies (Git concepts) — CONFIRMED, 7 items**
All in `git-dojo/lessons/`; each is technically wrong as stated, not a simplification:
1. `lesson-03/README.md:24-25` — "HEAD means 'the newest commit'". HEAD is the currently checked-out commit (usually the branch tip), not intrinsically the newest. 
2. `lesson-04/README.md:51-54` — "Switching branches physically swaps the files… genuinely separate worlds." Branches share history; switching updates tracked files only when permitted.
3. `lesson-04/README.md:78` — "Gone" after `branch -D`: the commit remains recoverable via reflog until pruned; only the ref is deleted.
4. `lesson-04/README.md:88-90` — `--no-ff` qualification: it forces a merge commit *when a fast-forward would otherwise happen*.
5. `lesson-06/README.md:7-10` — GitHub is "just a Git repository on someone else's computer": it's a hosting platform (auth, PRs, actions) backed by Git.
6. `lesson-06/README.md:60,67` — "byte-exact custody readback" / "proof-grade replication": matching HEAD hashes prove the same commit, not identical working trees/config/hooks/refs.
7. `lesson-06/README.md:96-97` — "Same verbs, same behavior" vs real GitHub: transport commands match; GitHub adds permissions/protection rules.
- Plus SUSPECTED: `dashboard src/content/tier1/module-1-5.tsx:174` — "search indexes every word in every file across all your repositories" overstates GitHub code search (permission-scoped, indexing limits).
- Fix: reword per above. No wrong command syntax/flags were found — all `git switch -c`, `merge --no-ff`, `revert --no-edit`, `restore --source= --`, `main..origin/main` usages are valid and current.
- Effort: S each

## Top 5 to fix first

1. **H1 + H2 — owner-gate progress and drills routes.** Live security gap on the published site; same one-line middleware fix already proven on the grader routes. Smallest effort, largest exposure.
2. **H3 — serialize crisis setup.** Only defect found that can destroy learner state (the practice repo) through normal concurrent use.
3. **M1 + M2 — error status + async error boundary.** Together they stop failures from masquerading as success or hanging requests; prerequisite for trusting monitoring.
4. **M6 + L10 — content accuracy.** This app's whole promise is teaching Git *correctly*; the HEAD/branch/`-D` misstatements teach wrong mental models that later lessons must undo.
5. **M4 + L5 — modal focus + form labels.** The highest-impact accessibility pair: without them, keyboard/screen-reader learners cannot reliably complete lessons at all.
