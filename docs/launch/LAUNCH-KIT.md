## Show HN draft

**Title:** `Show HN: Git Dojo – learn Git by working through safe, realistic scenarios`

**Post:**

I built Git Dojo because most Git learning starts with commands before learners understand what Git is protecting.

It is a free, open-source learning app with two independent paths:

- visual explanations that show what changes in a repository and why it matters
- a terminal practice course that creates disposable local repositories, so learners can make real commits, branches, conflicts, and recoveries without risking a real project

The terminal course includes nine scenarios, from first commits to remote push conflicts and reviewing a contractor delivery with a planted secret.

Live app: https://git-dojo.com<br>
Source: https://github.com/runtsai/git-dojo

I would especially value feedback on where Git explanations are still confusing or technically inaccurate.

## Reddit draft

**Title:** `I made a free open-source Git practice app with safe terminal scenarios`

**Post:**

I built Git Dojo to make Git feel less like a list of commands and more like a system for protecting work.

It has a visual learning path plus a command-practice course that creates throwaway repositories. You can make commits, branches, merge conflicts, remote push mistakes, and recoveries without touching a real project.

It is free and open source:

- Try it: https://git-dojo.com
- Source: https://github.com/runtsai/git-dojo

## Dev.to article outline

**Working title:** `I built Git Dojo to teach Git through consequences, not command memorization`

1. The problem: Git commands are easy to copy and hard to understand.
2. The principle: show what is happening before asking the learner to act.
3. The product: visual path, command practice course, and crisis scenarios.
4. Safety: every command lesson uses a disposable repository.
5. What surprised you while building it.
6. Invitation: try Git Dojo, report unclear lessons, or contribute.

## Low-cost launch order

1. Add a demo GIF and make the GitHub repository front page complete.
2. Create the `v0.1.0` release.
3. Share one community post where feedback is likely to be high quality.
4. Watch traffic and feedback for a few days.
5. Improve the README or onboarding based on real questions.
6. Then consider a larger post such as Show HN.
